
## 5. Verification discipline (earned, not aspirational)

- **Never trust a build exit code.** Today: a wrapper reported "exit code 0" while the log said
  `EXIT=1` with `sorryAx` silently in six theorems; and separately a build printed eight green
  `#print axioms` lines while `EXIT=1` on a syntax error. Grep the FULL log, every time.
- **An empty `lake` log is ambiguous** — blocked on the lock looks identical to compiling. Confirm
  with `pgrep`, and check audit line numbers match the patched file.
- **Never narrow a probe until it prints `true`.** If a check fails, diagnose; do not re-scope.
- **Build families only from definitions.** Never lift a config off the real orbit and feed it back
  into its own test — that is how a tautology passes for a confirmation.
- **Always include a control that SHOULD fail**, so a real match is distinguishable from a vacuous one.
- **Validate simulators against already-proven concrete instances before trusting them.**
- **Re-measure a subagent's claims *and* its self-doubt.** A dying agent's last sentence is the
  least-verified thing it produced.
- **Write the final combination line yourself.** §5bk was written by the integrator, not by any
  agent: had the independently built halves not fit, it would have failed to elaborate.
- **Give every agent the exact expected base commit.** Three agents today started from a stale base
