## §3 Epoch anatomy — the segment itinerary

`[MEASURED, k = 2..7; budget verified exact for k = 2..6]`

An epoch `M1(k) → M1(k+1)` is **exactly**

```
turn_0 ++ S0 ++ turn_1 ++ S1 ++ … ++ turn_k ++ S_k ++ tail
```

with **`k+1` ladder segments** `S0 … S_k`. Every `S_j` is a *rung ladder* (§4): the head's
successive state-`A` peaks advance by exactly `+3` cells and successive rung spans grow by
exactly `+6` steps. **No step is unaccounted for** — `budget_check()` confirms the sum equals the
epoch span for `k = 2..6`.

Itinerary (verified `k = 4..7`):

* the **up** segments `S0 … S_{J−1}` walk *up* the cascade, each partially consuming one comb block
  and stopping when the *next* `0`-gap is used up;
* the **main** segment `S_J`, `J = ⌊k/2⌋ + 1`, consumes the *top* comb `a(k)` completely with a
  **blank right side** — this is the phase that doubles the register and creates the new frontier;
* the **down** segments `S_{J+1} … S_k` walk back *down*, each **resuming** the comb its
  corresponding up-segment left half-eaten, with `(u, m) → (u+1, m−2)`, and finishing it.

**Rung-count laws `[MEASURED]`:**

```
main segment :  nrungs = a(k) + 2 ,        span0 = 6·a(k) + 15
up segment j :  nrungs = (next milestone gap)/3          -- gap-limited
down segment :  nrungs = comb_j − (rungs used by the matching up segment)
```

## §4 THE RUNG TILE — one ∀-parametric lemma covers 30 of 33 measured segments

This is the single most reusable finding. `[MEASURED — 30/33 segments over k = 2..7, exact]`

### Configuration shape

State `A`, head reads `0`. Writing the **`TapeCalc` left field nearest-first**:

```
IN(u, m, c, g)  :=  ⟨ .A , p ,
      ⟨ pow10 u ++ [1,1] ++ pow01 m ++ [0,0] ++ ones c ++ TAIL ,   -- left, nearest-first
        false ,                                                    -- head
        [1] ++ zeros g ++ REST ⟩⟩                                  -- right
```

In **tape order** (left → right) the neighbourhood reads

```
   … TAILᴿ   1^c  0 0  (1 0)^m  1 1  (0 1)^u  [head=0]  1  0^g  REST …
```

### The step law

```
steps ( 6·(u + m) + 15 )  IN(u, m, c, g)  =  some  IN(u+2, m−1, c+1, g−3)   at  pos + 3
```

* requires `m ≥ 1`, `c ≥ 1`, and (`g ≥ 3` **or** the right side is blank);
* `u + m` increases by exactly 1 per rung ⟹ successive spans grow by exactly `+6` — this is the
  `+6` seen in **every** segment of **every** epoch measured;
* the head advances `+3` per rung — this is the `+3` peak step.

**This is the doubling mechanism, cell-for-cell**: one `(1 0)` pair is eaten off the comb
(`m → m−1`, −2 cells) while **two** `(0 1)` pairs are emitted behind the head (`u → u+2`, +4 cells),
and the counter gains one (`c → c+1`). Net `+3` cells and a `×2` register — the `(2,4)` signature.

### Locality window (this is what makes it ∀-parametric)

`[MEASURED]` During one rung the head visits exactly

```
[ p − 2(u + m) − 4 ,  p + 4 ]
```

* it reaches **exactly** the first `0` of the `0 0` pair (the cell it overwrites to extend `1^c`)
  and **never reads inside `ones c`** ⟹ `TAIL` is completely arbitrary (`TapeCalc.steps_lpad_zeros`
  / `steps_lpad_dich`);
* it overruns the head position by exactly `+4` on the right ⟹ `REST` is arbitrary provided
  `g ≥ 3`, and the blank case is the `zeros`-padding case (`steps_rpad_zeros`, `steps_rpad_dich`).

### Segment exit dichotomy

```
nrungs(m, g, REST) = if REST = blank then m + 2 else min (m + 2, g/3 + 1)
```

* **comb-exhausted** exit (`m` hits 0): on the top rung the `1 1` / `0 0` boundary collapses and
  the two `ones` blocks fuse into a single one (exact instance in the worked example below; the
  general collapse identity was **not** derived and is `[OPEN]`). This is the **main** segment and
  the **down** segments.
* **gap-exhausted** exit (`g` hits `< 3`): the **up** segments; the head then crosses into the next
  comb block.

Segment step total:
```
Σ_{r=0}^{nrungs−2} ( span0 + 6r )  =  (nrungs−1)·span0 + 3·(nrungs−1)·(nrungs−2)
```
e.g. main segment of `k = 6`: `1245·7479 + 3·1245·1244 = 13 957 695` ✓.
